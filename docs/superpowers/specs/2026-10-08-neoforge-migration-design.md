## 迁移方法

采用现有代码增量适配。这与用户要求的“小改动沿用、差异过大再重写”一致：马达、球的运动和能量守恒、召唤上限等业务逻辑保留；加载器构建、注册、能力和物品数据等确实不兼容的接入点采用新版标准写法。

整模组重写会扩大行为回归范围，也会丢失已验证边界；引入同时兼容 Forge/NeoForge 的中间层会增加本次不需要的结构。因此只保留 1.21.1 NeoForge 的直接实现。

2. **马达与法术核心**：主 agent 适配 Create 持久化钩子、SavedData 工厂、tick 事件、Goety Spell/Focus 真实接口和放置事件。保留 128 RPM、8192 SU、12000 刻寿命、三台跨维度上限、永久马达、扳手无掉落及护目镜计时。
3. **流体与灵魂数据核心**：主 agent 适配 NeoForge `RegisterCapabilitiesEvent`、Goety 图腾/方舟数据和 ItemStack Data Components。保留模拟无副作用、实际接受量记账、满容量保护、耗尽形态和其他数据保留。三个 Create Mixin 只修改新版所需接口与经过确认的注入位置。
4. **实体、渲染与测试适配**：GPT-6-luna（max）完成同步数据 builder、实体生成包、渲染顶点和原 GameTest 新 API 适配；主 agent 核对业务行为和修复运行失败。不能通过减少测试或放宽断言获得通过。
5. **审查**：GPT-6-sol（high）审查实现与完整 diff，重点核对运行边界、能量守恒、客户端隔离、依赖/注入和测试覆盖。主 agent 修复审查问题，必要时交原负责代理修复基础部分。

任务按各自文件边界分工。共享构建或测试运行由主 agent 协调，避免多个代理同时改同一文件或争用游戏目录。
